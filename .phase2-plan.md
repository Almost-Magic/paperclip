# Paperclip Phase 2 — Enhanced Fleet Control

## Scope

Build on Phase 1's foundation to add real-time monitoring, authentication, and production hardening.

## Deliverables

### F1: WebSocket Real-Time Updates (vs. polling)
- Replace usePolling() hook with WebSocket connection
- Real-time terminal/hand status updates (0-delay vs. 3-5s polling)
- Task completion notifications
- Connection health monitoring

### F2: User Authentication & Authorization
- JWT token-based auth (no session storage)
- Role-based access control (operator, admin, viewer)
- Protect all endpoints with auth middleware
- Frontend login/logout UI

### F3: Persistent Task History
- Store tasks in PostgreSQL (Phase 1 has in-memory only)
- Task filtering, sorting, pagination
- Task replay/re-run capability
- Audit trail with timestamps

### F4: Enhanced Routing Logic
- Learn from command history (ML-lite: frequency-based)
- User preferences (saved routes)
- Fallback chain (primary → secondary → default)
- Command parsing with NLP-like intent matching

### F5: Production Hardening
- Rate limiting (10 req/s per IP)
- Request logging & monitoring
- Graceful error handling
- Health check with component status
- CORS configuration for production

### F6: Monitoring & Observability
- Task success/failure rates
- Average execution time per terminal/hand
- Fleet health dashboard metrics
- Error rate monitoring

## Risk Mitigation

- **WebSocket complexity**: Start with simple broadcast, upgrade to room-based later
- **Auth token refresh**: Implement refresh token rotation
- **Test suite asyncio issue**: Use pytest-xdist in Phase 2
- **Database migration**: Alembic for schema versioning
